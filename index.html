Pull و Push و PR

أسماء متشابهة، وأعمال مختلفة

العمليةالمعنىهل تُدخل التاسك إلى main؟
Pullجلب تحديثات من Remote ودمجها في الفرع المحلي الحالي وفق الاستراتيجية.تُحدّث نسختك المحلية، ولا ترفع شغلك.
Pushرفع Commits إلى فرع على GitHub.Push إلى فرع التاسك لا يغيّر main.
Pull Requestطلب مراجعة ودمج من فرع مصدر إلى فرع هدف.فتح الطلب وحده لا يدمج الكود.
PR ليست أمر git pull. الكود يدخل main عندما يدمج التيم ليدر الطلب بعد استيفاء الشروط.

Fetch و Sync في VS Code

اختر العملية التي تحتاجها

Fetch

يجلب معلومات وCommits Remote ويحدّث متابعتها، دون دمجها في ملفات عملك.

Pull

يجلب ثم يدمج التحديثات في الفرع الحالي.

Push

يرفع Commits المحلية إلى الفرع البعيد.

Sync Changes

ينفّذ Pull ثم Push للفرع المرتبط.

افحص اسم الفرع قبل الضغط. Sync ليس زر حفظ، ولا ينشئ PR.

فتح PR على GitHub

بعد رفع Commits على برانش التاسك

  1. افتح Repository على GitHub.
  2. اختر Compare & pull request، أو Pull requests ثم New pull request.

إعداد الحماية بواسطة التيم ليدر

مثال باستخدام Classic branch protection في مستودع مؤسسة

Repository → Settings → Branches → Add classic branch protection rule
  1. Branch name pattern: main.
  2. فعّل Require a pull request before merging وRequire approvals.
  3. اختر مراجعة واحدة على الأقل، وفعّل Dismiss stale pull request approvals عند تغييرات جديدة.
  4. فعّل Require conversation resolution. وأضف فحوص البناء المطلوبة إذا كانت موجودة في المشروع.
  5. فعّل Do not allow bypassing the above settings، وأبقِ Force pushes وDeletions غير مسموحتين.
نفّذ الإعدادات على main الفعلي، ثم اختبرها. لا تمنح الطلاب صلاحية Admin.

fix/HD-102-priority-badge
  1. كل طالب يبدأ من main المحدّث، ويعمل على برانشه فقط.

SAVE & PUBLISH YOUR WORK
git status
git add src/components/TicketCard.jsx
git diff --staged
git commit -m "Add ticket details toggle"
git push -u origin feature/HD-101-ticket-details
